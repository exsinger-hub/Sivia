# Sivia 完整工作流

[English](workflow.md) | 简体中文 · [返回 README](../README_ZH.md)

目标是得到科学依据明确、关键关系可读，并在用户要求时可编辑的图件。测试用于推动修正，不以“做完测试”替代“产出图件”。

## 从用户实际要求的阶段进入

| 请求 | 起点 | 本轮终点 |
| --- | --- | --- |
| 论文生成 Overview | 科学图意与视觉参考 | 实际图片＋完整 prompt，询问反馈及可选 PPT 阶段。 |
| 只要 prompt | 科学图意与完整 prompt | 交付 prompt，不调用生图。 |
| 修改图片 | 当前图片/prompt 与指定改动 | 修订图片＋完整 prompt，再次等待。 |
| 确认稿转可编辑 PPTX | 已锁定参考与对象清单 | 原生文件、预览及编辑/来源说明。 |
| 修改指定 PPT 对象 | 确切文档、页面与允许的改动 | 局部修改及回归检查。 |

已有明确确认稿时，不重复生图。忠实复刻与论文内容适配是不同任务：前者保留可见内容，后者依据科学来源替换获准字段。

## 1. 明确科学图意

阅读相关正文、公式和用户提供的实现，梳理研究问题、已有方法的关键局限、本文贡献，以及输入—操作—输出关系。影响解释的矛盾先核实，再落实到图中。用一句话明确读者应理解的核心信息。

选择值得进入本图的内容。重排、选择、合并、监督等机制需要对应的视觉对象与操作，不能只堆叠模块名。实现细节除非影响图意，否则留在正文。

正文、核实的代码和真实结果提供科学依据；参考图提供表达方式。确认稿进一步约束构图，但不会使虚构数值变成真实测量。

## 2. 选择配对视觉参考

阅读相关[知识库成图](../knowledge-base/README.md)及其**完整 prompt**，或用户指定参考。按表达任务选择，而不只看主题是否相似。提炼分区比例、重点层级、具体图形、颜色、标签和连线规则。

围绕新方法自身组织阅读路径。记录所选模板，不照搬其模型结构、公式或实验数值。见[模板选择规则](../skills/design-scientific-figure/references/prompt-templates.md)。

## 3. 编写并核验完整生产 prompt

逐项明确图意、画布、阅读路径，以及各区域的对象、位置、相对比例、连接、精炼标签、配色与排版。制作说明不进入图内。

保存将实际提交的完整文本，按**非空白字符数**与本图绑定模板比较，不得短于模板。不能靠重复形容词或编造科学内容凑长度。修订时整合保留约束与新要求，不能只提交一段差异描述。具体检查和工具用法见 [prompt 细节规则](../skills/design-scientific-figure/references/imagegen-prompt-detail.md)。

## 4. 生成、检查，然后暂停

调用当前可用生图工具，检查实际返回图片，而不只检查 prompt。核验方法关系、箭头方向、标签、层级和缩放后的可读性。在授权范围内修正明确缺陷，并保留各版图片与 prompt 的对应关系。

交付实际图片、完整 prompt 和简短设计说明；询问修改意见以及是否需要可编辑 PPT，然后暂停。在此期间不连接 PowerPoint/WPS。单纯认可图片不等于授权制作演示文稿。

## 5. 锁定并拆解确认稿

用户明确要求可编辑复刻后，记录确认版本、画布比例、分区边界、对象坐标、配色、字体层级、阅读顺序和连接路径。使用稳定对象名称与一份复刻规格，不要求用户重复确认已有事实。

先判断表示方式，再决定是否裁图：

- 标签、形状、运算符、网格、简单图标与图解，用原生对象或语义清楚的组合重建。
- 定量图表来自原始数值；实验影像和特征图来自真实来源，配对样本与显示条件保持一致。
- 复杂插画保留为独立素材，标签和箭头另外绘制。重新生成会改变已确认角色时优先保留原图；仅在许可范围内生成独立替换素材。

裁图按 `有效 DPI＝保留像素数×25.4÷放置尺寸 mm` 计算。30 mm 宽、以 300 dpi 为规划目标时至少需要 355 像素，修改 DPI 标签不能补充信息。检查实际 alpha，并在深浅背景下观察边缘。[素材生产规则](../skills/design-scientific-figure/references/asset-production.md)说明生图无法提供可用透明度时，如何使用获授权的本地遮罩。

## 6. 构建、恢复并继续推进

确认实际应用、后端和文档，保持桌面焦点。工具名称与 Windows COM 应用名称可能误导；检测结果与行为矛盾时，只读核实程序路径与注册信息，不能为绕过绑定失败而修改其他已打开文档。

新任务默认独立文件。按区域从背景到前景构建，保留原生文字与稳定名称；后端支持批处理时，不必缓慢逐线播放。文字样式设置后核对固定边界；分组后重新检查所有外部连接，因为分组可能把面板填充抬到箭头之上。

失败时，改变直接影响失败属性的操作：

| 失败 | 下一步 |
| --- | --- |
| 小裁图放大后不清楚 | 找原始素材、重建原生几何，或独立生成获准插画；确有来源上限则如实说明。 |
| 棋盘格被画进背景，没有真实透明度 | 先通过图像工具修正背景；仍失败时使用获授权且适合素材的遮罩，并检查边缘。 |
| 属性设置返回成功，但圆角、文字或箭头不对 | 检查真实属性和渲染，恢复边界或改用受支持的原生表示。 |
| 应用调用阻塞 | 停止继续向该实例写入，保留草稿与规格，推进不依赖它的工作。 |
| 不依赖阻塞应用仍可完成所需 PPTX | 用可用的独立原生 OOXML 候选文件重建，不混用旧实时对象，也不静默更换指定软件。 |
| 缺少目标软件的精确渲染 | 使用当前已可用的实际 PPTX 导入渲染器检查候选稿，目标软件核验仍标为待完成。 |

独立文件恢复是一种制作方式，不等于实时编辑，也不是承诺存在自动后备工具。遵守当前工具约束及指定实时文档要求。若恢复需要扩大权限、新增科学内容或改变构图，明确询问该选择；不反复重试相同阻塞操作，也不关闭用户应用。

[运行时恢复规则](../skills/edit-powerpoint-live/references/reconstruction-recovery.md)包含具体流程与经实际复刻发现的对象级修法。

## 7. 审阅真正要交付的文件

逻辑上区分四个角色：Designer 定义依据与设计；Drawer 构建；Reviewer 指出具体缺陷；Corrector 给出最小修改。可以由同一代理承担，但知情审阅或自审不能宣称为未预先知情的独立审阅。

每完成一区，以及分组和最终修正后，都检查原生结构与**实际 PPTX 的最新渲染**。核对准确文字、端点、图片拆解、层叠、裁切及目标尺寸下的参考对应。另行生成的同坐标 PNG 不能证明 PPTX 能正确渲染。推进依赖区域前修正已观察到的局部缺陷；缺少目标软件证据保持待核验，不阻塞安全的独立制作。

完整 Overview 使用 [prepare-overview-review.py](../scripts/prepare-overview-review.py)生成真正删除标题，以及删除标题和 L3 细节的 PPTX 副本，保留关键条件。渲染副本、转为灰度并记录物理宽度。先向未获知图意的审阅者展示简化版并保存回答，再展示保留细节的无标题灰度版并保存回答，最后才揭示彩色图与预期图意。见[审阅副本说明](../skills/audit-scientific-figure/references/review-copies.md)。微小局部修改只需范围内回归，不重复测试未改变的整体叙事。

科学对应、可编辑性、预览渲染、目标软件渲染、图意及物理尺寸可读性分别给出结论。对象数量、脚本成功或平均分不能抵消错误箭头和缺失证据。

## 8. 整理最终交付

交付目录保留一个明确命名的最终源文件与当前预览；中间版和审阅记录另存。必要时附独立可替换插画，以及允许分发的字体和许可证。

编辑说明区分原生、组合、矢量和位图，说明公式/图表是专门的原生对象还是文字/形状组合，以及连线是否自动附着。记录字体近似或安装需求、实际裁图分辨率和渲染器。示意数值与实测结果明确区分。

示例交付结构：

```text
delivery/
  figure.pptx
  figure-preview.png
  editing-notes.md
  fonts/                 # 仅在有需要且许可允许分发时
  illustrations/         # 可选的独立素材
```

可编辑文件、已检查预览和目标软件验证是不同交付状态。缺少所需渲染器时可以交付候选稿并明确待核验项；存在已观察到的实质缺陷时，不能宣称视觉验收通过。公开知识库投稿是另一项操作，需要对所含材料取得授权。
