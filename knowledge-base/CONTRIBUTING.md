# 贡献科研绘图案例

欢迎把你的优秀科研 Overview、完整 prompt 和迭代经验分享给 Sivia。我们希望积累能帮助下一篇论文作图的具体案例，而不仅是一张好看的图。

## 方式一：提交 Issue

打开[知识库投稿表](https://github.com/exsinger-hub/Sivia/issues/new?template=knowledge-base.md)，上传实际生成的图片，粘贴生成它时使用的完整 prompt，并说明哪些地方值得借鉴。**图片与 prompt 必须配套，不能用事后摘要代替生成输入。** 仅有图片、仅有 prompt 或来源补充，可以先提交为待补全参考，不作为完整案例收录。

## 方式二：提交 Pull Request

Fork 本仓库，在 `knowledge-base/cases/<简短英文案例名>/` 下添加案例，再更新[知识库索引](README.md)。完整案例必须有前三项；其余按实际情况提供，不创建空文件：

| 文件 | 内容 |
| --- | --- |
| `README.md` | 论文或任务背景、图的目的、风格标签、来源与许可、可借鉴的经验。 |
| `prompt.txt` | 与成图对应的完整生成 prompt，而非一句修改指令或事后摘要。 |
| `figure.png` / `figure.jpg` | 该 prompt 实际生成的图片，不是包含图片和提示词的长截图；标明是生成示例、草稿还是最终认可版。 |
| `feedback.md` | 用户反馈、改动理由、认可时间或仍未解决的问题。 |
| `figure.pptx` | 可选：忠实复刻后的可编辑文件。 |

多轮案例可以按 `v01/`、`v02/` 分目录保存 prompt、图片与反馈，并在案例说明中指出最终认可版本。若生成使用了参考图，应另外附上 `reference.png`（或可访问来源）并说明输入角色；参考图不能冒充该 prompt 的生成结果。修改版需保存实际编辑指令和所用输入图。

## 有价值的投稿内容

- 展示论文中的一个关系如何被转成可见的图形，而不只是列出模块名称。
- 说明为什么调整区域比例、密度、连线、图像字段或标签。
- 保留“prompt → 对应成图”的真实配对，不把后写的说明冒充实际生成输入。
- 区分用户对视觉的认可和科学内容的核对；未经认可的案例仍可作为参考或失败分析。
- 提供作者、来源链接和允许的使用方式；仅上传有权公开的内容，不附带患者信息、密钥或未经授权的未公开手稿。

维护者会检查来源、图文对应和可借鉴的经验后归类收录。提交不等于已被采用；单个案例获认可，也不会自动把它的布局变成所有论文必须遵守的模板。
