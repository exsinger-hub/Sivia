# Recover an editable reconstruction without losing its contract

Read for an approved-reference PPTX reconstruction, especially a dense mixed native/raster figure or a backend failure. Keep the existing reconstruction specification, object names and user approval; do not create a second design or a separate recovery registry.

## Establish what is actually connected

Use the adapter's status, capabilities and exact document binding. A tool name or COM `Application.Name` alone is not proof of Microsoft PowerPoint: Windows can register WPS behind `PowerPoint.Application`. If status is contradictory or rendering behavior disagrees with the detected host, inspect the executable/application path and COM registration read-only. Do not re-register Office, kill user applications or switch the requested software to make a tool label true. Record unknown identity as unknown.

Run a small probe only for a feature the reference actually needs: for example fixed text bounds, a custom silhouette, two arrowheads or a grouped connector. Check the resulting property or render, not merely the successful setter. Reuse a verified capability until a new observation contradicts it.

## Recover within the authorized output

An editable-PPTX request permits a different construction method for a new isolated file when the user did not require a particular live backend. It does not permit an unannounced switch from WPS to Microsoft PowerPoint, foreground interaction, modification of another open deck or regeneration of approved characters.

If a native operation stalls or repeatedly has no effect:

1. Identify the exact operation and failed property. Stop sending mutations to the same busy application. Keep the last saved draft and specification.
2. Cancel only a known task-owned worker if necessary; do not terminate the user's presentation process. Avoid unbounded z-order loops and unchanged retries.
3. Continue independent asset or geometry work that does not need the blocked host.
4. If a file-backed route is allowed and available, rebuild from the frozen specification into a **new native OOXML candidate**. Do not mix the old session's object handles with file-backed objects or overwrite an open file. Keep the original backend lock; the fallback is a separate file construction path, not an in-session host switch.
5. Use the installed file backend or an available native PPTX library under the current environment's tool rules. This reference does not promise an automatic fallback tool or install new software. If the environment forbids a separate path, or the user requires live editing of a specific document, explain the boundary and ask for the needed choice.

Build and inspect the new candidate by region using the renderer that is actually available. An unavailable target-application renderer leaves that gate pending; it need not stop file construction when exact-file rendering and local structure review are available. An observed local defect still requires repair before dependent work proceeds.

## Repairs demonstrated by dense-figure reconstruction

| Observed failure | Change the responsible operation | Recheck |
| --- | --- | --- |
| Text expands after its font/content is assigned | Restore frozen bounds after text styling; set margins, wrapping and autofit explicitly. Fit within the approved region rather than globally shrinking the figure. | Actual bounds and exact rendered line breaks. |
| Corner-radius or freeform setter reports success but has no effect | Use a supported native preset/composite, or a native path in the isolated file candidate. | Silhouette in the fresh PPTX render. |
| Solid/open arrows differ from the request | Use the host's actual enumeration; Office uses triangle `2`, open `3`. Preserve both ends of genuinely bidirectional routes. | Both arrowhead properties and their rendered directions. |
| Grouping hides cross-panel arrows | Group only intended internal objects; restore the foreground order of external routes and annotation labels. Preserve attached endpoint IDs. | Every incoming/outgoing route after grouping, not just before it. |
| A default circular-arrow or theme effect changes the icon | Set its supported geometry/effect explicitly, or reconstruct the exact symbol with editable paths/primitives. | All parts of the symbol, inherited shadows and final-size clarity. |
| A star, underline or callout blocks text/routes | Move or resize that decoration and the necessary local label only. Avoid opaque patches that cut a semantic path. | Full reference-sized view plus the affected close-up. |

Custom path editability is not automatic reattachment. Declare whether a route is an attached connector or an editable free curve; users may need to adjust free-curve endpoints after moving a group. Likewise, separate editable equation terms are not an Office equation object, and shape-based status bars are not data-backed charts.

## Inspect the exact file and package it honestly

Save the candidate and import/render **that PPTX**, including after final grouping and the last correction. A separately drawn SVG/PNG with matching coordinates is a design view, not evidence of PPTX rendering. Prefer the requested application's export; when unavailable, an available LibreOffice/Poppler or Artifact Tool import renderer can support a preview verdict with the actual renderer named. Neither establishes PowerPoint/WPS fidelity. Do not acquire an unprovided renderer merely because it appears here.

Use native/package checks for relevant failures: missing or changed text, broken picture relationships, dangling attached endpoints, slide dimensions, accidental whole-panel rasterization, and group membership. Visually classify bounding-box warnings: an intentional title underline can overlap its text box without crossing glyphs; a flow arrow through a paragraph is a defect. Counts do not establish faithful appearance.

For a complete overview, follow the Reviewer's real title/L3-hidden copy workflow. Derive grayscale from those actual copy renders and record physical size. Preserve each unprimed reading before disclosing the next view. A reviewer who already knows the story is informed; local final repairs do not retroactively make an earlier blind review a blind review of the final version. Local edits need scoped regression, not a new full blind test.

Deliver one clearly named editable source, its current preview, and short editing/source notes. Include independent illustration assets and redistributable fonts/licenses when useful; do not claim a font is embedded unless it is. List native/composite/vector/raster boundaries and retained-pixel limits, including source-resolution illustrations reused to preserve an approved character. Keep old candidates and review receipts outside the delivery folder.

Report separately: file saved, structure checked, exact-file preview reviewed, target application verified, and final-size readability. Missing evidence stays pending. No unresolved observed hard defect may be presented as a pass. Keep scientific disclaimers and production records out of the artwork; retain source schematic numbers as schematic rather than relabeling them as experiments.
